# Slice 09 — Compact Live Hierarchy

## Contract

Concurrent execution is understandable at a glance without overwhelming the conversation. Active work is visible; settled work is compact; waits and failures remain discoverable; high concurrency stays responsive.

## Seam

Reuse the recursive timeline renderer and virtualization. Graph-backed rows provide compact run/agent summaries and nested phase/task/tool rows. The same projection supplies sidebar and composer context. Long content opens in lazy detail.

## Playable evidence

A browser fixture route provides equivalent Claude delegated-agent/workflow/team and Codex parallel-agent scenes in idle, running, permission, retry, blocked, failed, and high-concurrency states.

## Verification

Run browser behavior, keyboard navigation, ARIA expansion, narrow viewport, virtualization, progress-coalescing, and large-tree performance checks. Capture candidate screenshots for each state.

When a current/baseline shot exists, run `compare-screenshots` to judge candidate versus baseline. Run an independent `screenshot-critique` as the final visual check for every changed visual surface. Open shots for a non-blocking human checkpoint, allow roughly five minutes, then decide from evidence and record the rationale if no response arrives.

Finish with the global repository gates and real-app verification.

## Firewalls

Do not replace the timeline renderer. Do not auto-expand settled trees. Do not expose provider controls without an observed supported operation. Do not let progress deltas grow history or render cost without bounds.

## Human feedback

Feedback changes hierarchy density, default expansion, labels, and detail placement. It does not change the execution graph contract unless the UI exposes a semantic gap.
