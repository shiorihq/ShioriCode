# Slice 02 — Execution Contracts

## Contract

Provider evidence can describe a stable execution run/node graph without embedding Claude or Codex assumptions in shared consumers.

## Seam

Schema-only contracts define run kind, node kind, lifecycle, execution mode, provider aliases, correlation provenance, relationships, graph deltas, observed capabilities, and lightweight graph/detail RPCs. Legacy activities decode unchanged only as a migration input; they do not acquire new execution semantics.

A delegated agent, workflow, and team are distinct run kinds. Provider-only information belongs in optional typed facets or retained native evidence, not universal required fields.

## Playable evidence

Schema tests decode representative Claude, Codex, and legacy examples and render a provider-neutral graph JSON snapshot.

## Verification

Round-trip every delta variant; reject impossible identifiers; default additive fields for older clients; prove lifecycle and relationship schemas accommodate unresolved/out-of-order nodes. Keep `packages/contracts` free of runtime logic.

## Firewalls

Do not put full transcripts or native payloads in graph schemas. Do not mirror provider method rosters. Do not add controls to the contract without an observed capability.

## Human feedback

Feedback changes this slice if the taxonomy cannot express a captured flow without provider-name branching in shared consumers.
