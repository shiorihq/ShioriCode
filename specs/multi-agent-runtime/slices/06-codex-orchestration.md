# Slice 06 — Codex Orchestration

## Contract

Codex collaboration ancestry and terminal outcomes survive ordering changes and restart. Child plan/status/progress/failure events remain visible under the correct receiver thread, and multiple receivers retain separate detail streams.

## Seam

The app-server manager retains every valid JSON-RPC envelope before filtering. The adapter emits execution facts from collaboration items and receiver thread IDs. Persistent graph aliases replace transient maps as the authority. Dynamic tool calls use registered handlers or return a typed unsupported result.

## Playable evidence

Replay modern and legacy app-server fixtures, including child-before-parent and multiple receivers, then rebuild graph projections and query every receiver transcript.

## Verification

Cover nested/parallel receivers, process death, failed/cancelled/stopped tasks, progress without a payload ID, unknown items/methods, dynamic calls, and pending provider requests interrupted by restart. Never coerce an unknown completion into success.

## Firewalls

Canonical graph state survives provider death; dead JSON-RPC request IDs do not. Do not infer Claude workflow/team semantics. Unknown events are diagnosed, not presented as assistant content.

## Human feedback

Feedback changes this slice if a current app-server fixture reveals a stronger exact identifier or a different terminal-state source.
